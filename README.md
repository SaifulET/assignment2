Explanation of:
     * Merge vs Rebase
     * Squash & Reword

     
Merge: Combines branches and creates a merge commit, preserving the entire history of both branches. It’s ideal for collaboration but can lead to a cluttered history.
Rebase: Reapplies changes from one branch onto another, creating a linear history without merge commits. It’s great for a cleaner history but rewrites commit history.


Squash & Reword
Squash: Combines multiple commits into a single commit, simplifying the history (e.g., when you want to clean up small or redundant commits before merging).
Reword: Allows modifying the commit message of an existing commit without changing its content, useful for correcting commit messages.
